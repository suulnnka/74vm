## 1. 总览

任何计算机(CPU)的本质都是一个永不停止的三步循环:

```
取指 (Fetch)   →  译码/执行 (Decode/Execute)  →  取指  →  …
   PC → 存储器        控制器发出一串控制信号,
                      数据在寄存器/ALU/存储器之间搬运
```

VM-8 用 **46 个元件**把这四个环节全部摆在你面前:

| 环节 | 元件 | 真实 CPU 中的对应物 |
|---|---|---|
| 取指 | PC(2×74161) + MAR(74374) + 程序 ROM(74S472) + IR(74374) | 程序计数器 / 地址寄存器 / 指令寄存器 |
| 译码 | 3 片控制 ROM(74S472×3) + 定序器(74161) | 微码控制器(8086/8051 内部就是这种结构) |
| 执行 | A/B 寄存器(74175×4) + ALU(74283×2+7486×2) + Z 标志(7474) | 累加器 / 算术逻辑单元 / 标志位 |
| 存储 | 程序 ROM 74S472(512B) + RAM 6116(2KB) | 固件 Flash / 内存 |
| IO | 输入口 74245 + 键码锁存 74374 + LCD1602 | 端口 / 键盘控制器 / 显示器 |

**没有一块 CPU 是"黑魔法"** — 8080、Z80、6502 内部的微码控制器与 VM-8 的三片控制 ROM 是同一个思想:
把每条指令拆成若干个节拍, 每个节拍由一组控制信号(开门信号)完成一次搬运。

## 2. 硬件架构

```
                 ┌────────────── 8 位数据总线 ──────────────┐
                 │                                          │
  ┌────────┐  /CO  ┌────────┐   A0~A7  ┌─────────┐  D0~D7   │
  │  PC    │◄─────►│ pcbuf  │          │ 程序ROM │══════════╡  (/RO 使能, 74S472 512B)
  │74161×2 │       │ 74245  │          │ 74S472  │          │
  └─┬──────┘       └────────┘          └─────────┘          │
    │ CE=计数 / ~PL=跳转装载                                │
  ┌─┴──────┐  MI    ┌────────┐  A0~A7  ┌─────────┐          │
  │  MAR   │◄═══════╡ 总线   ├────────►│ RAM6116 │══════════╡  (/RI=读使能 /WE=写窗)
  │ 74374  │        └────────┘         │  2K×8   │          │
  └────────┘                           └─────────┘          │
  ┌────────┐  II                                              │
  │  IR    │◄═════════════════════════════════════════════════╡  (只喂控制ROM地址)
  │ 74374  │        ┌────────┐                                │
  └───┬────┘   AI──►│   A    │──/AO──►总线   A,B 均为 74175×2  │
      │        BI──►│   B    │  (B 恒可见, 供 ALU)             │
      │             └───┬────┘                                │
      │                 │ B⊕SUB                               │
      │             ┌───┴────┐   A + (B⊕SUB)                  │
      └──A0~A7─────►│  ALU   │ =74283×2 加法器 + 7486×2 异或   │
        (控制ROM    │74283×2 │────/EO──►总线, 和=0 → Z 标志    │
         地址)      └────────┘                                │
  ┌────────┐  OI                                               │
  │  OUT   │◄═══════ 总线 ──► LCD1602 数据脚 (RS/E 由微码产生)  │
  │ 74374  │                                                   │
  └────────┘                                                   │
  ┌────────┐  /TI                                              │
  │输入口  │◄═══════ 总线 ◄── bit0=秒标志  bit1=键标志          │
  │ 74245  │                                                   │
  └────────┘   ┌────────┐  KO                                   │
               │键码锁存│◄═══════ 总线 ◄── PS/2 扫描码           │
               │ 74374  │                                       │
               └────────┘                                       │
  ┌────────────┐   地址 = {节拍3位, IR.bit3, 操作码4位}          │
  │ 控制 ROM   │◄── 定序器 74161 (6 节拍/指令, 下降沿计数)         │
  │ 74S472 ×3  │   输出 24 位控制信号 ────────────────────────────┘
  └────────────┘   (每片 8 位: mc0 / mc1 / mc2)
```

### 关键时序约定

- **主时钟 4kHz**(右键可改): 每拍 250µs。定序器在**下降沿**推进节拍; 寄存器在**上升沿**写入
  (写入使能 = 微码信号 AND 主时钟, 如 `MAR.CK = CLK·MI`)——这样控制行在半周期内稳定, 每行恰好提交一次。
- **一条指令 = 4~6 拍**: T0/T1 取指令, T2 取操作数(两字节指令), T3~T5 执行。
- **RAM 写保护**: `/WE = NAND(RW, sysclk)` — 只有微码在执行拍内拉起 RW 才开写窗, 其余任何时刻总线抖动都写不进 RAM。

## 3. 指令集

VM-8 是**累加器架构**: 大多数运算围绕 A 寄存器进行。指令长度 1~2 字节, 高 4 位是操作码,
第二字节(若有)是 8 位立即数或 RAM 地址。共 16 条指令, 覆盖"取数-运算-存数-分支-IO-控制"的最小闭环。

| 编码 | 助记符 | 格式 | 功能 | 节拍 | Z 标志 |
|---|---|---|---|---|---|
| `0x0` | NOP | — | 空操作 | 4 | 不变 |
| `0x1` | LDI | `LDI imm` | A ← imm(装载立即数) | 5 | 不变 |
| `0x2` | LDA | `LDA addr` | A ← RAM[addr](取内存) | 5 | 不变 |
| `0x3` | STA | `STA addr` | RAM[addr] ← A(存内存) | 5 | 不变 |
| `0x4` | ADI | `ADI imm` | A ← A + imm(8 位回绕) | 5 | 和=0 置 1 |
| `0x5` | ADA | `ADA addr` | A ← A + RAM[addr] | 6 | 和=0 置 1 |
| `0x6` | CPI | `CPI imm` | 比较 A 与 imm(不回写) | 5 | 相等置 1 |
| `0x7` | CMA | `CMA addr` | 比较 A 与 RAM[addr] | 6 | 相等置 1 |
| `0x8` | OUT | — | LCD 写数据(字符) | 4 | 不变 |
| `0x9` | CMD | — | LCD 写指令(清屏/定位) | 4 | 不变 |
| `0xA` | JMP | `JMP addr` | 无条件跳转: PC ← addr | 4 | 不变 |
| `0xB` | JZ | `JZ addr` | Z=1 才跳转 | 4 | 不变 |
| `0xC` | JNZ | `JNZ addr` | Z=0 才跳转 | 4 | 不变 |
| `0xD` | KBD | — | A ← 键码寄存器(PS/2 扫描码) | 4 | 不变 |
| `0xE` | TCK | — | A ← 输入口(bit0=秒脉冲, bit1=新按键) | 4 | 不变 |
| `0xF0` | CLF | — | 清键标志 | 4 | 不变 |
| `0xF8` | CLT | — | 清秒标志 | 4 | 不变 |

> **为什么没有减法/移位/调用?** 减法已经藏在 CPI/CMA 里(ALU 的 SUB 信号做 `A + ~B + 1`);
> 其他指令只是控制 ROM 没烧对应行 —— 加一条指令 = 加一行微码, 这正是微码架构的可扩展性,
> 见 [教学练习](#10-教学练习建议)。

### 每条指令的微操作(节拍级)

以最复杂的 `ADA addr`(A 加上内存)为例, 6 拍的完整故事:

| 节拍 | 控制信号 | 动作 |
|---|---|---|
| T0 | /CO, MI | PC → 总线 → MAR (指令地址) |
| T1 | /RO, II, CE | ROM[addr] → 总线 → IR, **PC+1** |
| T2 | /CO, MI, CE | PC(操作数地址) → MAR, **PC+1** |
| T3 | /RO, MI | ROM → 总线 → MAR (操作数地址装入 MAR) |
| T4 | /RI, BI | RAM[MAR] → 总线 → B |
| T5 | /EO, AI | ALU(A+B) → 总线 → A, 同时和=0 则置 Z |

其余指令同构, 差别只在 T3~T5 的三行微码(比如 `CPI` 的 T4 用 `EO+SUB` 且不给 AI —— 结果算出来只影响标志不回写)。
在 `js/examples.js` 顶部的 `VM8_MC` 里可以看到全部 16 行的微码真值表。

### 汇编器

示例内置一个两遍扫描的迷你汇编器(`VM8.assemble`), 支持:

- 标签: `MAIN:   TCK` — 跳转目标可写标签;
- 常量: `SEC1 = 0x10`(只能引用数字或其他常量);
- 注释: `;` 之后全部忽略;
- 数字: 十进制(`48`)或十六进制(`0x3A`)。

程序上限 **254 字节**(PC 是 8 位, 0xFF 之后回绕; 汇编器会在越界时报错)。

## 4. 微码

### 控制字

每片控制 ROM 输出 8 位, 三片拼成 **24 位控制字**, 每一位就是一根控制线:

| ROM | 位 | 信号 | 有效电平 | 含义 |
|---|---|---|---|---|
| mc0 | D0 | CO | 低 | PC 输出到总线 (~CO) |
| mc0 | D1 | MI | 高 | 总线装入 MAR |
| mc0 | D2 | RO | 低 | 程序 ROM 输出 (~RO) |
| mc0 | D3 | II | 高 | 总线装入 IR |
| mc0 | D5 | RI | 低 | RAM 读(驱动总线) (~RI) |
| mc0 | D6 | RW | 高 | RAM 写窗口(与 CLK 相与成 /WE) |
| mc0 | D7 | CE | 高 | PC 计数(+1) |
| mc1 | D0 | AI | 高 | 总线装入 A |
| mc1 | D1 | AO | 低 | A 输出到总线 (~AO) |
| mc1 | D2 | BI | 高 | 总线装入 B |
| mc1 | D3 | EO | 低 | ALU 输出到总线 (~EO) |
| mc1 | D4 | OI | 高 | 总线装入 OUT |
| mc1 | D5 | KO | 低 | 键码寄存器输出 (~KO) |
| mc1 | D6 | TI | 低 | 输入口输出 (~TI) |
| mc1 | D7 | RS | 高 | LCD RS=1(数据) / 0(指令) |
| mc2 | D0 | TF | 低 | 清秒标志 |
| mc2 | D1 | KF | 低 | 清键标志 |
| mc2 | D2 | SUB | 高 | ALU 做减法(B 取反 +1) |
| mc2 | D3 | E | 高 | LCD E 选通(与 CLK 相与成单脉冲) |
| mc2 | D4 | JP | 低 | 分支: 无条件装载 PC (~PL) |
| mc2 | D5 | JM | 低 | 分支: JZ 条件项 |
| mc2 | D6 | JN | 低 | 分支: JNZ 条件项 |
| mc2 | D7 | RUN | 高 | 运行位: 0 时主时钟停振(停机, 留给 HLT 练习) |

### 译码 = 一个 512×24 的查找表

控制 ROM 的 8 位地址拼法: `A = {操作码 IR[7:4], IR[3], 节拍[2:0]}`, 即

```
A7..A4 = 操作码   A3 = 指令子位   A2..A0 = 定序器节拍
```

于是"译码"不需要任何逻辑设计 —— **不同指令在不同节拍该发什么信号, 就是查一次表**。
空闲行(如 step≥6 的不可达行)全部烧成"无信号"值, 保证定序器回绕瞬间不误动作。

这就是真实微码 CPU(8086、8051)的核心思想; 现代 CPU 用 PLA/硬连线替换了 ROM 查表, 但节拍-控制字的模型不变。

## 5. RAM 与 ROM 的使用

VM-8 有两个存储器, 职责完全不同:

| | 程序 ROM(74S472 PROM) | RAM(6116 SRAM) |
|---|---|---|
| 容量 | 512×8, 电路只用低 256B(A8 接地) | 2048×8, 电路只用低 256B(A8~A10 接地) |
| 内容来源 | **烧录**(非易失, 断电保持) | 程序运行时读写(**易失**, 断电丢失) |
| 谁写 | 烧录器 / 74VM 的右键菜单 | 只有 STA 指令(经 /WE 写窗) |
| 谁读 | 取指与取操作数(/RO) | LDA / ADA / CMA(/RI) |
| 地址来源 | PC → MAR → A0~A7 | MAR → A0~A7 |

### 内存布局约定

```
程序 ROM (74S472)                 RAM (6116)
0x00 ┌────────────────┐          0x00 ┌────────────────┐
     │ 程序代码         │   PC 从    │ (约定保留)       │
     │ (初始化段在最前)  │  0000H    0x0F └────────────────┘
     │ 主循环            │  开始执行 0x10 ┌────────────────┐
0xF7 └────────────────┘              │ 程序变量区       │  ← 出厂时钟程序:
     0xF8~0xFF 未用                    │ (各程序自行约定)  │     0x10~0x15 = 时/分/秒 BCD
                                     0xFF └────────────────┘
```

**为什么变量从 0x10 开始?** 这只是程序库的约定 —— 0 页留白便于教学讲解"零页"概念(6502 的零页寻址就住在 0x00~0x00FF)。
出厂时钟程序把 6 个 BCD 变量放在 `0x10~0x15`(秒个/秒十/分个/分十/时个/时十)。

### RAM 与 ROM 在机器里的分工(以时钟程序为例)

- 代码(`LDI/OUT/ADI…`)全部住在 ROM —— 断电不丢, 上电即可运行;
- 时间值(现在几点)住在 RAM —— 断电丢失, 所以每次开机程序都先执行"清零 + 显示 00:00:00"的初始化段;
- **ROM 只读**: 即使总线冲突/程序跑飞, /WE 写窗不开就写不进 RAM, 更写不进 ROM —— 这就是"程序不可自改"的硬件保证。

## 6. ROM 的初始载入

### 真实硬件怎么做

74S472 是**熔丝型 PROM**: 出厂全 0/全 1, 用户用编程器一次性烧断熔丝写入内容, 之后不可更改。
实际制作 VM-8 这类面包板计算机时, 通常用 **AT28C64B/AT28C256 EEPROM**(74VM 元件库里也有):
可以在电路上靠 /WE 反复擦写, 写入用一根 Arduino/树莓派拉地址总线逐字节写即可。

### 在 74VM 里怎么把程序放进 ROM

VM-8 示例的程序 ROM 带 `vm8-program` 标签, 右键它有三个入口:

1. **📥 载入 VM-8 程序…** — 打开内置程序库(计数器 / 迎宾动画 / 打字机 / 秒表 / 出厂时钟),
   选择后立即烧入 `props.mem` 并**自动冷启动**(等效重新上电, PC=0 从头执行)。程序以汇编源码随库存放,
   烧入前经内置汇编器汇编;
2. **编辑内容 (十六进制)…** — 直接粘贴/编辑 512 字节的十六进制(每行 16 字节), 适合对照手写机器码教学;
3. **导出内容 (十六进制文件)** — 把当前 ROM 内容存成 `.prom.hex` 文件, 可分享、可再用粘贴导入。

> 其他电路中的任意 ROM/EEPROM(74187/74S472/AT28C64B/AT28C256)同样支持 2、3 两个通用入口;
> 程序内容随电路**自动保存**在浏览器 localStorage, 也可用 文件→导出 JSON 带走整套"硬件+固件"。

### 出厂内容与"空跑"

新放置的 ROM 出厂内容 = 地址值(地址 n 处存着 n)。若不烧程序直接开机, CPU 会从 0000H 起
顺序"执行"这些字节 —— 和真机一样, 总线上的随机内容也会被当成指令跑飞。**上电能运行, 是因为 ROM 里已有正确的程序**。

## 7. IO 是怎么连接的

VM-8 没有统一编址的 IO 空口(那是 8080/ Z80 的做法), 而是**每个外设一根专线** —— 更接近 6502 的存储映射思路的简化版:

### 输出口: LCD1602

```
OUT 寄存器 (74374) Q1~Q8 ──► LCD D0~D7   (OI: A→OUT, RS/E 控制写入时机)
微码 RS ─────────────────► LCD RS       (1=写字符, 0=写指令)
微码 E AND sysclk ───────► LCD E        (上升沿锁存, OUT 指令 T4 拍产生单脉冲)
```

软件视角: `LDI 'H' → OUT` 就是在屏幕上打一个 H; `LDI 0x01 → CMD` 清屏; `LDI 0x80 → CMD` 光标回 (0,0),
`0xC0` = 第二行行首。LCD 内部 DDRAM 地址在每次写入后自动 +1(0x27 之后跳 0x40, 即换行), 所以连续 OUT 就是连续打字。

### 输入口: 74245 汇流的两位状态

```
秒标志 (7474 FF2) ──► 74245 B0 ─┐
键标志 (7474 FF1) ──► 74245 B1  ├─ /TI 使能时 B→A 驱动总线 ←── TCK 指令读入 A
GND ──────────────► B2~B7 ─────┘
```

- **秒标志**: 1Hz 时钟(与电源开关相与)上升沿把 FF 置 1(D=VCC); 程序 `TCK` 看到 bit0=1 后必须 `CLT` 清掉 —— 这是**电平标志**的轮询协议: 硬件置位, 软件应答清零;
- **键标志**: PS/2 键盘每发完一字节由捕获电路置位; 软件取走键码后 `CLF` 应答;
- 若秒脉冲与新键同拍到达, TCK 返回 `0x03` —— 程序里 `CPI 1 / CPI 2 / CPI 3` 的分派顺序就是为此设计的。

### PS/2 键盘捕获链(纯硬件外设芯片)

```
PS/2 键盘 ──CLK──► 反相 ──► 74164 移位 CK + 74161 位计数 CK   (下降沿采样, DATA 稳定)
          ──DATA─► 74164 A·B (串行移入)
74161 数到 9 (8 数据位齐) ──► LATCH 脉冲: 键码锁存进 74374 + 置键标志
74161 数到 11 (帧结束)   ──► CLEAR 脉冲: 计数器/移位器清零, 等下一帧
键码寄存器 74374 ──/KO──► 总线 ←── KBD 指令读走
```

这一链路**完全不经过 CPU**: 扫描码到达与锁存是纯硬件完成的, CPU 只在方便时用 KBD 取走 —— 这就是真实计算机"中断/缓冲"思想的轮询简化版。
两处解码(count9/count11)都用 PS/2 的 CLK 选通, 是为了把计数器 9→10 迁移瞬间的一拍毛刺挡在门外(电路里有详细注释)。

### 已知竞态(教学彩蛋)

按键帧恰好落在程序执行 `CLF` 的那一拍, 键标志会被刚置位就清除, 该键丢失 —— **重按即可**。
真实的键盘控制器用 FIFO 缓冲解决这个问题; 让 VM-8 加一个 4 字节键缓冲环形队列, 是一个极好的练习。

## 8. 开机 / 关机 / 重启

VM-8 有**两级电源控制**, 对应真实计算机的两个层次:

### 8.1 电路上的电源开关(计算机级)

示例里有一颗 **「电源开关」**(SW, 初始为开), 它像真实单板机的电源闸刀一样接进四个地方:

| 接入点 | 关断效果 |
|---|---|
| 主时钟门 `sysclk = CLK·PWR·RUN` | CPU 全部寄存器停止计时 |
| 1Hz 秒脉冲门 `1Hz·PWR` | 实时时钟输入停止 |
| PC 与定序器的 `~CLR` | **关机期间保持复位**(PC=0) |
| 键盘 LATCH 脉冲门 `LATCH·PWR` | 关机时按键不被捕获 |

- **关(关机)**: 整机静止, LCD 保持最后一帧画面, RAM/寄存器内容保留;
- **开(开机)**: 复位释放, PC 从 0000H 起跑, 程序重新执行 —— LCD 被程序的初始化段清屏重画。
  注意 RAM 并不清零(上电复位电路不清 SRAM), 但时钟程序开头就把变量清零 —— **"程序自己负责初始化"是固件的第一课**。

### 8.2 仿真菜单的 开机 / 关机 / 重启(整机级)

菜单 **仿真(S)** 提供**整个电路**的电源控制, 语义贴近"对整块面包板通断电":

- **关机**: 全部芯片断电 —— 输出呈 X/高阻, 时钟停振, 待决事件清空; 状态栏显示 `⏻ 已关机`;
- **开机**: 等效上电复位 —— 触发器/计数器/移位寄存器清零, **RAM 清零**(易失), **ROM/EEPROM 保持**(非易失),
  LCD 屏面清空等待程序初始化, 时钟从 0 相位重新起振, 振荡类电路重新扰动自启动;
- **重启**: 断电再上电(二者的组合)。

与 8.1 的区别: 菜单开机把 **RAM 也清零**了(整机断电), 而电路开关只复位 CPU 时序(等效按复位键)。
用哪个教学? 讲"SRAM 易失性"用菜单重启; 讲"复位向量与自初始化"用电路线开机。

> 右键程序 ROM → 载入程序后也会**自动冷启动**一次, 保证新程序从 0000H 干净地跑起来。

## 9. 内置程序库

全部程序只用第 3 节的 16 条指令, 源码就在 `js/examples.js`(烧入后亦可右键 ROM 看十六进制)。难度递进:

### 9.1 计数器 (70 字节) — "Hello World"

轮询 1Hz 秒脉冲, 在 LCD 第一行显示 `00~59` 循环。要点: 电平标志的"读-清"协议、BCD 进位链、数字→ASCII(`+48`)。

```asm
SEC1  = 0x10            ; 秒个位 (BCD)
SEC10 = 0x11            ; 秒十位
        LDI 0x01        ; 清屏
        CMD
        LDI 0
        STA SEC1
        STA SEC10
        JMP SHOW        ; 先显示 00, 再进轮询
LOOP:   TCK             ; A = 输入口: bit0=秒脉冲
        CPI 1
        JZ TICK
        CPI 3           ; 秒+键同拍: 先走秒
        JZ TICK
        JMP LOOP
TICK:   CLT             ; 应答: 清秒标志
        LDA SEC1
        ADI 1
        CPI 10
        JZ C1
        STA SEC1
        JMP SHOW
C1:     LDI 0           ; 个位回 0, 十位 +1
        STA SEC1
        LDA SEC10
        ADI 1
        CPI 6
        JZ C10
        STA SEC10
        JMP SHOW
C10:    LDI 0           ; 59 → 00
        STA SEC10
SHOW:   LDI 0x80        ; 光标回 (0,0)
        CMD
        LDA SEC10
        ADI 48          ; BCD → ASCII
        OUT
        LDA SEC1
        ADI 48
        OUT
        JMP LOOP
```

### 9.2 迎宾动画 (57 字节) — 最小程序之一

逐字打出「你好 74VM-8!」(GB2312 中文 = 连续写两个 ≥0x80 的字节), 然后轮询**键标志**: 按任意键(取走并判非 break 码 0xF0)清屏重播。

### 9.3 打字机 (139 字节)

数字键 0~9 回显到 LCD, 空格=空格, Enter=换到第二行(`LDI 0xC0 + CMD`), Esc=清屏, 其余键忽略。
**它同时是一面镜子**: 每个键要 `CPI+JZ` 两查一跳(7 字节/键), 26 个字母就装不下了 —— **没有变址寻址/查表指令的 ISA 表达力就这么大**。
这正是真实 CPU 演化出间接寻址、CALL/RET、中断向量表的动力, 见练习 4。

### 9.4 秒表 (181 字节)

显示 `MM:SS`, 空格=启动/暂停, C=清零。在计数器之上引入一个**状态变量** `RUN`(0x10): 每秒 tick 到来时先看 RUN 是否为 1 —— 用 RAM 中的一个字节存"机器状态", 这就是最朴素的状态机。

### 9.5 出厂时钟程序 (248 字节) — 综合应用

示例默认烧录的程序: 1602 显示 `HH:MM:SS` 走时, PS/2 键 A=时+1、C=秒清零。RAM `0x10~0x15` 存 6 个 BCD 位,
主循环 = `TCK 轮询 → 事件分派(秒tick/新键) → BCD 进位 → 刷新显示`。配套 `test/test-cpu.js` 123 项自动化测试。

## 10. 教学练习建议

由浅入深, 每题都只需改动汇编源码(右键程序 ROM → 编辑内容, 或改 `js/examples.js` 里的源码):

1. **改显示**: 让计数器显示 `00~99`; 让秒表显示 `S:SS`(带冒号)。
2. **加键**: 给计数器加"按 C 清零"(参考秒表的 KEY 分派)。
3. **退格键**: 给打字机加退格 —— 提示: 用一个 RAM 变量跟踪 LCD 光标地址, 写字符后 +1,
   退格时 -1 并 `LDI 0x80 → ADD 光标 → CMD` 重新定位, 再写一个空格抹掉。
4. **为什么需要变址寻址**: 数一数打字机给键盘全映射需要的字节数, 与"一张 256 项 ASCII 表 + 间接寻址"对比,
   写一段 200 字的分析。
5. **加一条 HLT 指令**: 操作码 `0xF4` 已空闲。需要: ① 微码行 T3 烧 `RUN=0`(mc2 D7=0) —— 主时钟停振;
   ② 讲清楚"停机后谁来恢复"(提示: 电源开关)。改 `js/examples.js` 的 `VM8_MC` 后跑 `node test/test-cpu.js` 验证。
6. **加 CALL/RET 为什么难**: PC 只有 74161 没有堆栈指针; 设计一个"返回地址存固定 RAM 单元"的一级调用, 体会硬件堆栈的必要性。
7. **观察微码**: 右键三片控制 ROM 看十六进制, 对照第 4 节的表核一行(如 `0xA3` = JMP 的 T3 行)。
8. **键缓冲**: 用 RAM 做一个 4 字节环形队列 + 头/尾指针, 解决第 7 节的 CLF 竞态丢键问题 —— 这就是 16550 串口 FIFO 的雏形。
